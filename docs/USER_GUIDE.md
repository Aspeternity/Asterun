## 3 分钟快速开始

1. 从 [最新稳定版 Release](https://github.com/Aspeternity/Asterun/releases/latest) 下载与你系统架构对应的 ZIP。
2. 把 ZIP **完整解压**到一个长期使用、可写的目录，例如 `D:\Tools\Asterun`。
3. 运行 `Asterun.exe`。
4. 按 **Alt + Space** 呼出启动器。
5. 直接输入程序名、快捷词或路径的一部分。
6. 用 **↑ / ↓** 或 **Tab** 选择结果，按 **Enter** 启动。
7. 按 **Esc** 隐藏启动器。

Asterun 默认使用 **Modern Compact（现代紧凑）** 界面，默认界面语言为简体中文。运行时设置、快捷项、使用记录和搜索缓存保存在程序目录旁的 `data/` 中。

第一次使用时，不需要先配置一大堆选项。建议先正常搜索和启动几次常用程序，等熟悉基本操作后，再按需要开启 Everything、自定义快捷项或调整快捷键。

## 最常用的键盘操作

Asterun 的核心思路是：**呼出以后尽量不用鼠标。**

| 操作 | 默认按键 | 说明 |
| --- | --- | --- |
| 呼出 Asterun | **Alt + Space** | 全局快捷键 |
| 打开快捷项管理 | **Alt + S** | 全局快捷键 |
| 上 / 下一项 | **↑ / ↓** | 结果列表循环选择 |
| 下一项 / 上一项 | **Tab / Shift + Tab** | 适合左手连续操作 |
| 执行当前结果 | **Enter** | 启动程序、打开文件或执行快捷项 |
| 快速执行编号结果 | **1–9 / 0** | 1–9 对应第 1–9 项，0 对应第 10 项 |
| 打开设置 | **F2** | 启动器打开时可用 |
| 在文件管理器中定位 | **Ctrl + Enter** | 适用于可定位的结果 |
| 复制选中目标 | **Ctrl + Shift + C** | 复制目标文本/路径 |
| 隐藏启动器 | **Esc** | 不退出后台程序 |

这些动作可以在 **设置 → 快捷键** 中修改。全局快捷键与启动器内快捷键是分开的：前者在 Asterun 后台运行时也能触发，后者只在启动器窗口中生效。

如果某个全局快捷键被 PowerToys、输入法、其他 Launcher 等程序占用，Asterun 会提示热键冲突，但不会因此强制退出。进入 **设置 → 快捷键** 改成其他组合即可。

## 搜索技巧与智能排序

Asterun 不要求你完整输入程序名。搜索框可以直接输入：

- 程序名称的一部分；
- 自定义快捷词；
- 中文、拼音或拼音首字母；
- 英文首字母或模糊片段；
- 路径片段；
- 开启 Everything 后的文件名和文件夹名。

例如 TeamSpeak 不一定要完整输入 `TeamSpeak`，平时习惯输入 `team` 或 `ts` 都可以。中文程序开启 **启用拼音搜索** 后，也可以用拼音习惯进行查找。

Asterun 还会把你的**使用频率和最近使用情况**作为排序信号。也就是说，如果某个查询下你经常选择同一个结果，它会逐渐更靠前。正常使用即可，不需要手动维护“常用程序排行榜”。

如果你想重新开始学习记录，可以进入 **设置 → 数据 → 清除使用历史**。

如果某个刚安装或刚移动的程序没有及时出现，可以使用 **设置 → 数据 → 重新建立程序索引**。

## 智能数字键快速执行

这是 Asterun 比较有特色、也最容易第一次让人疑惑的功能。

开启 **设置 → 常规 → 搜索与执行 → 数字键快速执行结果** 后，结果右侧会按顺序对应：

`1 2 3 4 5 6 7 8 9 0`

其中 **0 表示第 10 项**。

通常情况下，看到目标排在第 2 项，直接按 `2` 就可以快速执行，不必先按 ↓ 再按 Enter。

但 Asterun 不会把所有数字都粗暴地当成“结果编号”。它会判断这个数字更像是在**继续输入**，还是更像在**执行结果**。

例如你想搜索：

`v2rayN`

已经输入 `v` 后继续按 `2`，Asterun 会检查 `v2` 是否存在明显的搜索延续。如果 `2` 更像是程序名的一部分，就会把它作为文本继续输入，而不是误执行第二项。

因此你可能会发现：

- 有时按数字会立即启动对应结果；
- 有时数字会正常进入搜索框；
- 在 Everything 动态结果仍在确认时，Asterun 可能短暂等待后再决定。

这不是随机行为，而是为了减少“程序名里带数字却误启动结果”的情况。

如果你完全不需要这个功能，可以在 **设置 → 常规** 关闭 **数字键快速执行结果**，数字键就会恢复为普通输入。

## Everything 文件与文件夹搜索

Asterun 默认已经可以搜索 Windows 程序来源；Everything 是一个**可选的文件与文件夹搜索扩展**。

<p align="center">
  <img src="assets/readme/settings-search-sources.webp" alt="Asterun 搜索来源设置" width="820">
</p>

### 开启方法

进入：

**设置 → 搜索来源 → 文件与文件夹 → Everything 文件与文件夹**

如果当前没有检测到可用的 Everything，页面会提供 **获取并启动 Everything**。Asterun 托管模式会获取兼容的稳定版本，并负责必要的校验、启动和状态维护。

Everything 正常运行后，Asterun 的搜索结果中就可以出现本地文件和文件夹。

### 如果你已经装了 Everything

Asterun 会区分**自己托管的 Everything**和**用户自行维护的 Everything**。如果系统里已经存在兼容实例，Asterun 的原则是不无条件接管用户已有安装。

页面状态会告诉你当前是：

- Everything 正在运行；
- 未检测到可用 Everything；
- 正在准备 / 下载 / 校验 / 连接；
- 检测到多个实例；
- 准备失败。

遇到状态不一致时，可以先点 **重新检测**。

### “显示 Everything 托盘图标”是什么

这个选项只控制 **Asterun 托管的 Everything** 是否显示自己的托盘图标。

它和 Asterun 自己的 **显示系统托盘图标** 是两件不同的事：

- Asterun 托盘图标：Asterun 自己的后台入口；
- Everything 托盘图标：Everything 自己的后台入口。

如果你只想让 Everything 默默为 Asterun 提供搜索，可以关闭 Everything 托盘图标。

## 自定义快捷项：从“打开程序”到动态参数

这是整份教程里**最值得认真看的一节**。

如果你只是给一个便携程序起一个好记的快捷词，只需要填写前面几个基础字段；但一旦用到 **运行时输入、固定参数、工作目录、`{input}`**，就已经是在配置一条真正的“动态命令”。这些字段如果不理解，很容易出现“能搜到但启动方式不对”的情况。

按 **Alt + S** 打开 **Asterun 快捷项管理**，或者从托盘菜单进入快捷项管理，然后选择 **新建快捷项**。

### 先分清每个字段是干什么的

| 字段 | 是否常用 | 作用 |
| --- | --- | --- |
| **快捷词** | 必填 | 你在 Asterun 里输入什么来找到它。多个快捷词用逗号分隔，第一个优先级最高。 |
| **名称** | 推荐填写 | 搜索结果中显示的名称。 |
| **目标** | 必填 | 真正要打开的程序、网址、文件夹或命令目标。 |
| **目标类型** | 通常用自动识别 | 自动识别 / 应用程序 / 网址 / 文件夹 / 命令行。只有自动识别不符合预期时再手动指定。 |
| **运行时输入** | 按需 | 让快捷项接收你这一次临时输入的内容。 |
| **测试输入** | 仅配置时使用 | 只给“测试”按钮使用，用来验证动态参数；它**不会保存成永久参数**。 |
| **固定参数** | 进阶常用 | 每次启动都会传给目标程序的固定命令行参数，也可以放 `{input}`。 |
| **工作目录** | 少数场景需要 | 程序启动后的“当前目录”，主要影响相对路径、脚本和依赖当前目录的程序。 |
| **以管理员身份运行** | 按需 | 启动时请求管理员权限，会触发 Windows UAC。 |

如果只是添加一个普通程序，最常见的配置其实只有：

```text
快捷词：vpn
名称：v2rayN
目标：D:\Tools\v2rayN\v2rayN.exe
目标类型：自动识别
运行时输入：不接受额外输入
```

**固定参数、工作目录都可以留空。**

---

### 多个快捷词怎么用

例如：

```text
快捷词：ts, team, teamspeak
```

以后输入 `ts`、`team` 或 `teamspeak` 都能找到同一个快捷项。

第一个快捷词是主快捷词；后面的可以理解成别名。

---

### 目标和“目标类型”

目标决定 Asterun 最终交给 Windows 的对象。

常见情况：

- `D:\Apps\Tool\Tool.exe` → 应用程序
- `https://example.com` → 网址
- `D:\Research\` → 文件夹
- `.bat` / `.cmd` / `.ps1` 等脚本 → 命令行

大多数情况下保持 **自动识别** 就够了。

一个很重要的原则是：

> **目标里主要放“要执行谁”，参数放到“固定参数”。**

不要把下面这种整串内容都塞进“目标”：

```text
D:\Apps\tool.exe --mode fast --profile work
```

更推荐：

```text
目标：
D:\Apps\tool.exe

固定参数：
--mode fast --profile work
```

这样目标、参数和工作目录各自职责清楚，也更容易测试和维护。

---

## 固定参数：每次启动都要带上的内容

**固定参数会在每一次执行这个快捷项时传给目标程序。**

它适合“这个快捷项永远都需要这些参数”的场景。

例如你想专门做一个“Chrome 无痕模式”快捷项：

```text
快捷词：
private

目标：
C:\Program Files\Google\Chrome\Application\chrome.exe

运行时输入：
不接受额外输入

固定参数：
--incognito
```

以后输入 `private`，实际效果就相当于：

```text
chrome.exe --incognito
```

再比如让记事本永远打开同一个文件：

```text
快捷词：
todo

目标：
notepad.exe

固定参数：
"D:\Notes\todo.txt"
```

这里路径两边的双引号很重要，因为路径可能包含空格。

### 固定参数要不要写引号？

Asterun 会把“固定参数”作为参数字符串交给 Windows，**不会替你猜每个参数应该怎么分组，也不会自动给路径加引号**。

所以：

```text
--file D:\My Notes\todo.txt
```

对于某些程序可能会被理解成多个参数。

更稳妥的是：

```text
--file "D:\My Notes\todo.txt"
```

如果目标程序自己的命令行文档要求引号、短横线或特定参数格式，就按那个程序的规则填写。

---

## 运行时输入：让同一个快捷项接收“这一次”的内容

固定参数是不变的；**运行时输入是每次使用时临时变化的。**

这是两者最核心的区别。

例如：

- 固定参数：`--reuse-window`
- 运行时输入：这一次想打开的项目目录

### 实际怎么输入？

假设快捷词是：

```text
g
```

那么使用动态输入时，搜索框格式是：

```text
快捷词 + 空格 + 输入内容
```

例如：

```text
g 心脏 MRI
```

Asterun 会把第一个词 `g` 识别成快捷词，把后面的：

```text
心脏 MRI
```

作为本次运行时输入。

快捷词的别名同样可以这样使用。

---

### 三种运行时输入模式

#### 1. 不接受额外输入

这是普通快捷项的默认选择。

例如：

```text
vpn
todo
private
```

输入快捷词以后直接启动，不需要额外内容。

如果你只是打开程序、固定网址、固定文件夹，保持这一项即可。

#### 2. 原样传递

Asterun 会把你输入的内容**原样**交给目标。

适合：

- IP 地址；
- 文件路径；
- 搜索词交给本地程序；
- 命令行参数；
- 项目名称等。

例如输入：

```text
ping 8.8.8.8
```

其中 `8.8.8.8` 就是运行时输入。

#### 3. URL 编码（UTF-8）

这个模式主要用于把文字放进 URL 查询参数。

例如输入：

```text
g 心脏 MRI
```

Asterun 会把空格和中文编码成适合 URL 的形式，例如空格会变成 `%20`。

**不要把这个模式用于普通程序参数**，否则程序收到的可能会是 `%20`、`%E5...` 这样的编码文本。

## `{input}`：告诉 Asterun“把动态内容放这里”

只要开启了运行时输入，就可以在下面三个位置使用：

```text
目标
固定参数
工作目录
```

占位符统一写：

```text
{input}
```

运行时，Asterun 会把所有 `{input}` 替换成本次输入。

### 应用程序 / 命令行有一个自动规则

如果目标类型是：

- **应用程序**
- **命令行**

并且你开启了运行时输入，但**完全没有写 `{input}`**，Asterun 会把运行时输入自动追加到固定参数最后。

例如：

```text
目标：
ping.exe

运行时输入：
原样传递

固定参数：
-n 4
```

输入：

```text
ping 8.8.8.8
```

最终参数相当于：

```text
-n 4 8.8.8.8
```

这是一个方便的简写。

但如果输入可能包含空格，或者你需要控制它插入在哪个位置，**更推荐明确写 `{input}`**。

---

### 路径带空格时，建议写 `"{input}"`

“原样传递”不会自动替你加引号。

比如你想把一个项目目录交给 VS Code：

```text
D:\Research\CKD Project
```

如果固定参数只写：

```text
--reuse-window {input}
```

目标程序可能把带空格的路径拆成多个参数。

更推荐：

```text
--reuse-window "{input}"
```

这样输入：

```text
code D:\Research\CKD Project
```

最终效果相当于：

```text
Code.exe --reuse-window "D:\Research\CKD Project"
```

---

## 为什么 URL / 文件夹更依赖 `{input}`

对于“应用程序 / 命令行”，Asterun还能把运行时输入自动追加到参数末尾。

但对：

- **网址**
- **文件夹**

Asterun无法合理猜测动态内容应该插在什么位置。

因此这类动态快捷项应该明确放置 `{input}`。

例如网页搜索：

```text
快捷词：
g

目标类型：
网址

目标：
https://www.google.com/search?q={input}

运行时输入：
URL 编码（UTF-8）
```

输入：

```text
g 心脏 MRI
```

Asterun 会先对“心脏 MRI”进行 UTF-8 URL 编码，再替换目标里的 `{input}`，最后打开搜索页面。

如果选择了运行时输入，却既没有 `{input}`、目标类型又无法自动追加，快捷项编辑器会提示配置不完整，而不是静默保存一个无效配置。

---

## 工作目录：大多数时候应该留空

“工作目录”最容易被误解。

它**不是程序文件所在位置的另一种写法，也不是参数栏**。

工作目录表示：

> 程序启动以后，把哪个文件夹当作它的“当前目录”。

这主要影响：

- 使用相对路径的脚本；
- 会读取当前目录配置文件的工具；
- 类似 `config\settings.json` 这样的相对路径；
- 某些老程序或命令行工具。

对于普通应用程序 / 命令行快捷项，如果目标是明确的绝对路径，并且工作目录留空，Asterun 会在可以确定时自动使用目标所在目录。

所以普通用户的原则很简单：

> **不知道工作目录有什么用，就留空。**

只有目标程序明确要求特定当前目录时再设置。

例如：

```text
目标：
D:\Tools\Report\run.cmd

固定参数：
config\daily.json

工作目录：
D:\Tools\Report
```

这样脚本里的相对路径 `config\daily.json` 才会从 `D:\Tools\Report` 下解析。

工作目录本身也支持 `{input}`，但这是更高级的用法，只有你确实需要“根据本次输入切换当前目录”时才建议使用。

## “测试输入”和“测试”按钮一定要用

只要配置了运行时输入，建议保存前先测试。

例如你的快捷项是：

```text
快捷词：
ping

目标：
ping.exe

运行时输入：
原样传递

固定参数：
-n 4 {input}
```

在“测试输入”填写：

```text
8.8.8.8
```

然后点 **测试**。

Asterun 会按当前编辑器里的配置实际启动一次目标，让你确认：

- `{input}` 是否放对位置；
- 引号是否正确；
- 固定参数是否被目标程序接受；
- 工作目录是否正确；
- 是否真的需要管理员权限。

**测试输入只是测试数据，不会变成以后每次启动都使用的固定值。**

## 三个可以直接照着理解的完整例子

### 例 1：Google 动态搜索

```text
快捷词：g
名称：Google 搜索
目标类型：网址
目标：https://www.google.com/search?q={input}
运行时输入：URL 编码（UTF-8）
固定参数：留空
工作目录：留空
```

使用：

```text
g 心脏 MRI
```

适合：网页搜索、站内搜索、带 query 参数的网址。

---

### 例 2：Ping 任意地址

```text
快捷词：ping
名称：Ping
目标：ping.exe
目标类型：应用程序
运行时输入：原样传递
固定参数：-n 4 {input}
工作目录：留空
```

使用：

```text
ping 8.8.8.8
```

实际含义：

```text
ping.exe -n 4 8.8.8.8
```

适合：命令行工具、IP/主机名测试、动态参数。

### 例 3：用 VS Code 打开任意项目目录

```text
快捷词：code
名称：VS Code 项目
目标：选择 Code.exe
目标类型：应用程序
运行时输入：原样传递
固定参数：--reuse-window "{input}"
工作目录：留空
```

使用：

```text
code D:\Research\CKD Project
```

这里故意把 `{input}` 放在双引号中，这样带空格的目录仍然作为一个参数传给 VS Code。

## 快捷项高级配置最常见的错误

| 情况 | 为什么不对 | 建议 |
| --- | --- | --- |
| 把 `exe + 参数` 全塞进“目标” | 目标和参数职责混在一起，后续难以识别和测试 | 可执行文件放“目标”，参数放“固定参数” |
| 路径参数带空格却没加引号 | 目标程序可能把它拆成多个参数 | 根据目标程序规则使用 `"{input}"` 或 `"D:\My Path"` |
| URL 动态搜索选“原样传递” | 中文、空格、`&` 等可能破坏 URL | 查询参数通常选“URL 编码（UTF-8）” |
| 普通程序参数选“URL 编码” | 程序会收到百分号编码文本 | 本地程序通常选“原样传递” |
| 开启运行时输入，但 URL / 文件夹里没有 `{input}` | Asterun不知道动态内容应该放哪里 | 在目标或其他合适字段明确加入 `{input}` |
| 把“测试输入”当永久参数 | 测试输入不会作为快捷项配置保存 | 永久内容写“固定参数” |
| 不知道工作目录用途却随便填 | 可能改变程序解析相对路径的行为 | 普通应用保持留空 |
| 动态配置不先测试 | 很难发现引号、参数顺序、工作目录问题 | 保存前用“测试输入 + 测试”验证 |

对于绝大多数用户，先掌握 **快捷词、目标、固定参数、运行时输入、`{input}`** 这五个概念，就已经能覆盖大部分高级快捷项需求。

## “发送到 Asterun”

进入：

**设置 → 常规 → Windows 与启动 → 添加到“发送到”菜单**

开启后，Windows 的“发送到”菜单中会出现 **Asterun**。

之后可以：

**右键程序 / 文件 → 发送到 → Asterun**

把选中的路径交给 Asterun 的快捷项创建流程。对于经常把便携程序加入 Asterun 的用户，这比先打开快捷项管理再浏览文件更快。

在 Windows 11 上，根据系统右键菜单样式，你可能需要先进入 **显示更多选项** 才能看到“发送到”。

### 这个入口为什么 Asterun 退出后还在

这是正常的。

“发送到 Asterun”属于一个**持久的 Windows Shell 集成**。它的意义就是即使 Asterun 当前没有显示启动器，也可以从资源管理器把文件交给 Asterun。

因此：

- 正常退出 Asterun：不会删除这个入口；
- 在设置中关闭“添加到‘发送到’菜单”：会撤销这个入口；
- 运行 `Uninstall.exe`：v1.0.3 会校验所有权后清理 Asterun 自己创建的 `Asterun.lnk`。

如果你启用了这类系统集成，不再使用 Asterun 时更推荐运行 `Uninstall.exe`，而不是直接删除整个文件夹。

## 设置页怎么用

教程不逐项重复所有开关，只需要知道每一页主要解决什么问题：

| 页面 | 什么时候需要进去 |
| --- | --- |
| **常规** | 调整开机启动、托盘、SendTo、拼音搜索、数字键快速执行、窗口位置等日常行为。 |
| **快捷键** | 修改 Alt + Space、Alt + S、F2 等快捷键，或处理快捷键冲突。 |
| **搜索来源** | 控制开始菜单、Windows Apps、App Paths、PATH 和 Everything。Everything 的详细用法见前文。 |
| **外观** | 切换 Modern Compact / Classic，以及简体中文 / English。 |
| **数据** | 导入导出快捷项、清除使用历史、重新建立程序索引、恢复默认设置。 |
| **关于** | 查看版本、检查更新、设置是否接收预发布版本。 |

其中有两个选项值得单独提醒：

- **仅剩一个结果时立即执行**：效率高，但比较激进。新用户建议先保持关闭，熟悉搜索行为后再决定是否开启。
- **接收预发布版本更新**：普通用户建议保持关闭，继续使用 Stable；只有明确参与测试时再开启。

真正需要学习成本的不是这些普通开关，而是 **智能数字键、Everything 和自定义快捷项高级参数**，因此教程把篇幅重点放在这三部分。

## 便携使用、更新与卸载

### Asterun 是便携应用

Asterun 不需要传统安装器。把 Release ZIP 解压后即可运行。

主要运行时数据位于：

```text
Asterun/
├─ Asterun.exe
├─ Update.exe
├─ Uninstall.exe
└─ data/
   ├─ settings.json
   ├─ commands.json
   ├─ usage.json
   └─ provider-cache.json
```

因此备份 Asterun 时，通常把整个目录一起备份即可。

### 不建议在压缩包里直接运行

请先完整解压到普通可写目录。Asterun 需要写入本地 `data/`，目录不可写时，设置、快捷项和使用记录可能无法正常保存。

### 更新

进入 **设置 → 关于**：

- **自动检查更新**：后台检查稳定更新；
- **接收预发布版本更新**：测试用户使用；
- **检查更新**：立即手动检查。

正式稳定版 Release 同时提供 x64、ARM64、SHA-256 校验文件和更新清单。

### 什么时候需要 Uninstall.exe

因为 Asterun 是便携应用，单纯没有开启任何外部集成时，删除文件夹就能移除主体文件。

但如果你开启过：

- 开机启动；
- “发送到 Asterun”；
- Asterun 托管的 Everything 相关系统状态；

更推荐运行 **Uninstall.exe**，让 Asterun 先清理自己创建的外部状态，再删除程序目录。

特别是“发送到 Asterun”属于程序目录之外的 Windows Shell 快捷方式；直接删除程序目录以后，已经不存在的 Asterun 无法再执行清理逻辑。

## 常见问题

### 1. Alt + Space 没反应

最常见原因是全局快捷键被其他软件占用。

检查：

**设置 → 快捷键 → 主呼出快捷键**

Asterun 检测到冲突时会提示，但会继续驻留，不会因为热键失败直接退出。

### 2. 搜索不到某个刚安装的程序

先尝试：

**设置 → 数据 → 重新建立程序索引**

如果目标本来是一个没有注册到 Windows 程序来源的便携程序，也可以直接创建自定义快捷项。

### 3. 搜索不到文件

文件 / 文件夹搜索依赖 Everything。

检查：

**设置 → 搜索来源 → Everything 文件与文件夹**

并确认页面状态显示 Everything 可用。

### 4. 为什么结果顺序会变化

这是正常的智能排序行为。Asterun 会结合搜索匹配和使用记录调整结果顺序。

如果想清空学习记录：

**设置 → 数据 → 清除使用历史**

### 5. 为什么按数字没有启动对应结果

开启智能数字键后，Asterun 会判断数字是：

- 搜索内容的一部分；
- 还是你想执行对应编号结果。

例如 `v2rayN` 中的 `2` 更可能被当成继续输入。这是为了减少误启动。

### 6. 为什么 Asterun 退出后“发送到 Asterun”仍然存在

因为这是持久 Shell 集成，正常退出不应该撤销它。

关闭：

**设置 → 常规 → 添加到“发送到”菜单**

或者不再使用软件时运行 `Uninstall.exe`。

### 7. 为什么托盘里有两个图标

可能分别是：

- Asterun；
- Everything。

如果不需要 Everything 自己显示托盘图标，可以在 **设置 → 搜索来源** 关闭 **显示 Everything 托盘图标**。

### 8. 设置或快捷项保存不了

确认 Asterun 所在目录可写。不要把它长期放在压缩包、只读目录或需要特殊权限的系统目录中。

## 推荐的新用户设置

如果你不想研究太多选项，可以先保持下面这套思路：

- 使用 **现代紧凑**；
- 保持 **Alt + Space**；
- 保持 **启用拼音搜索**；
- 保持 **数字键快速执行结果**；
- “仅剩一个结果时立即执行”先关闭；
- 需要文件搜索时再开启 Everything；
- 自动更新保持稳定通道；
- 有便携程序时，用快捷项或“发送到 Asterun”添加。

熟悉几天后，再按自己的工作流修改快捷键、窗口位置、动态快捷项和预发布更新。

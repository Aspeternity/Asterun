# Asterun 1.1 Release Validation

Asterun 1.1 continues the 1.0 stable line; the publication gates are unchanged from [V1.0_RELEASE_VALIDATION.md](V1.0_RELEASE_VALIDATION.md). This file records each 1.1.x release.

## 1.1.1 release validation

- Version: `1.1.1`; Windows fixed FileVersion/ProductVersion: `1.1.1.30000`.
- Settings / Commands / Usage / Provider Cache schemas remain 12 / 2 / 2 / 27; no persisted field was added (`notifiedVersion` already existed in `update-state.json`).
- Fresh update offers: showing About re-checks a displayed offer at most once a minute; a fetched manifest replaces or clears it, a failed fetch keeps it. Download and install fetches the manifest again first, installs the newest release, stops when none is newer, and falls back to the offered release if the fetch fails. A version found by a check started from Settings is recorded as notified. The new behaviour takes effect once 1.1.1 is installed.
- Hand-tested with a 1.0.9-versioned build against the live v1.1.0 release: About refresh, one-minute freshness window, re-check before download, cancel, install, and no repeated notification.
- Local Release suite 62/62 (two environment-gated skips) and `verify_branding.py`, `verify_version.py`, `verify_release_contract.py`, `verify_icon_resources.py`, `verify_tag_version.py v1.1.1`.
- Stable publication must pass the release workflow's version/tag, resource, Windows runtime, dual-architecture package, SHA-256 and public update-manifest gates. Physical ARM64 runtime acceptance is not claimed.

## 1.1.0 release validation

- Version: `1.1.0`; Windows fixed FileVersion/ProductVersion: `1.1.0.30000`.
- Settings / Commands / Usage / Provider Cache schemas remain 12 / 2 / 2 / 27; no persisted field was added.
- Update check timing: every launch checks once, 30 seconds after startup and regardless of the 6-hour throttle, so the startup notice has gone before an update notice can appear. Tray-resident checks keep the hourly evaluation with the 6-hour throttle. The new behaviour takes effect once 1.1.0 is installed; earlier versions still check by their own rules.
- Local Release suite 62/62 (two environment-gated skips) and `verify_branding.py`, `verify_version.py`, `verify_release_contract.py`, `verify_icon_resources.py`, `verify_tag_version.py v1.1.0`.
- Stable publication must pass the release workflow's version/tag, resource, Windows runtime, dual-architecture package, SHA-256 and public update-manifest gates. Physical ARM64 runtime acceptance is not claimed.
